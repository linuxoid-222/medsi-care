# Ограничения безопасности MEDSI Care

MEDSI Care — синтетический исследовательский прототип. Safety-событие не
является диагнозом, медицинским заключением или назначением лечения.

## Правило MVP

Версия правила: `safety-v1`. Событие создаётся только для факта, который:

1. сохранён после подтверждения пользователем;
2. имеет `polarity=present`;
3. относится к одной из явно заданных категорий: `chest_pain`,
   `shortness_of_breath`, `loss_of_consciousness`, `stroke_signs`,
   `severe_bleeding`.

Неподтверждённый текст и ответ LLM сами по себе не создают safety-событие.
Событие содержит исходное evidence, сохраняется в `monitoring_events` и
создаёт уведомление доверенному лицу. Интерфейс показывает консервативную
рекомендацию обратиться за срочной медицинской помощью.

Набор правил предназначен для демонстрации архитектуры и требует отдельной
медицинской и нормативной оценки перед любым реальным использованием.

## Редакция и исторические доказательства

Подтверждение привязано к `text_revision`; устаревший запрос отклоняется с 409.
Safety-event сохраняет самостоятельный `text_provenance` только с фактами,
вызвавшими правило: check-in/fact IDs, revision, category/polarity, цитата,
временной контекст, UTC-время записи/подтверждения, `safety-v1` и
`resolution=direct_confirmation`. Изменение check-in не переписывает событие.

Окно обычных фактов 24 часа не отменяет уже сохранённое safety-событие.
Позднейшее отрицание/пустое подтверждение также не удаляет событие и уведомление.
F7/F8 исправлены: одинаковое подтверждение возвращает прежний event без
новых уведомлений; ручной редактор UI доступен при отказе extraction. Подробнее: [FACTS.md](FACTS.md).

Идемпотентность опирается на check-in/text/facts revision и правила safety,
а не время повторного HTTP-запроса. Новое содержательное подтверждение/редакция
может создавать новое событие; клиническая модель эпизодов не заявляется.
Ручной факт остаётся черновиком до явного подтверждения с evidence-валидацией.
Подробности и legacy-границы: [IDEMPOTENCY.md](IDEMPOTENCY.md).
