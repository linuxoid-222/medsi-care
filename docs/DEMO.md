# Демонстрация MEDSI Care

Состояние проверено 10 ноября 2026 года. Только синтетические сообщения и
профиль `profile-demo`. Демонстрация функциональности не является независимой
оценкой качества Method C. Архив, split, пороги и результаты research-v2
не изменяются.

## Фактическая готовность

| Участок | Статус и предел подтверждения |
| --- | --- |
| Текстовый ввод | Реализован; ранее проверен реальным локальным API/UI, persistence — PostgreSQL P0.8 |
| Реальный GigaChat extraction | Проверен реальным компонентом в этом блоке: OAuth, GigaChat-2, schema/evidence, неподтверждённые факты; это adapter smoke, не полный UI-путь |
| Голосовая запись в браузере | Реализована через MediaRecorder/getUserMedia; настоящая запись с микрофона пока не проверена |
| Локальное распознавание | Реализовано faster-whisper; тесты используют FakeModel. Прежняя загрузка модели не считается проверкой распознавания настоящего аудио |
| Исправление транскрипта | Реализовано: сохранение транскрипта как check-in, поле исправленного текста, PATCH; API-контракт проверен тестами. Полный путь после настоящего ASR не проверен |
| Извлечение и подтверждение фактов | Extraction отдельно проверен реальным GigaChat; confirmation с evidence проверен API/тестовым provider и persistence. Совместный реальный UI-путь пока не проверен |
| Числа и подтверждённые факты → анализ | Реализовано; объединение фактов проверено тестами, числовой API smoke — PostgreSQL. Полный путь после реального голоса пока не проверен |
| Сохранение события | Реализовано; проверено реальным PostgreSQL и API P0.8 |
| Уведомление caregiver | Реализовано; реальный UI/read проверен P0.7, PostgreSQL — P0.8. Внешней отправки SMS/email нет |
| Недоступность LLM | Реализованы контролируемые ошибки и явный резервный режим UI; сохранность ручного дневника/числового анализа проверена тестами. Live: HTTP 404 несуществующей модели и искусственно вызванный сетевой timeout; это не авария реального сервиса |

Готовы текстовая часть и реальный adapter smoke. Полная мультимодальная
демонстрация пока не объявляется проверенной: запись с микрофона → настоящий
faster-whisper → исправление → реальный extraction → подтверждение в UI →
событие и caregiver остаётся следующим блоком.

## Подготовка окружения

Команды выполнять из корня репозитория. Нужны Python >=3.12, Node/npm,
PostgreSQL и браузер с поддержкой MediaRecorder. Только localhost или HTTPS
для микрофона. Сначала установить зависимости, если ещё не установлены:

```bash
python3 -m venv .venv
.venv/bin/pip install -e 'backend[dev]'
npm --prefix frontend ci
cp .env.example .env
```

Не перезаписывать уже настроенный `.env`: копирование нужно только при первом
запуске. Установить в нём `MEDSI_STORAGE=postgres`, `DATABASE_URL` своей
локальной синтетической базы, `MEDSI_DEMO_MODE=true`.

Для PostgreSQL через Compose:

```bash
docker compose up -d db
set -a
source .env
set +a
.venv/bin/alembic upgrade head
```

Если Docker socket недоступен, использовать существующий локальный PostgreSQL
с корректным `DATABASE_URL`; этот путь уже проверен P0.8. Не выдавать запуск
на SQLite/in-memory за проверку PostgreSQL. Основную базу не удалять.

### Локальные credentials GigaChat

Секреты вводятся только в локальный файл вне Git, например в уже используемый
`/home/linuxoid/Projects/secret.env`, или в игнорируемый `.env`. Не отправлять
их в чат. Не хранить во frontend и не включать в видеозапись терминала.

Переменные:

- `GIGACHAT_AUTH_KEY`: Authorization Key проекта;
- `GIGACHAT_MODEL`: идентификатор модели, доступной этому проекту;
- `GIGACHAT_SCOPE`: scope проекта;
- `GIGACHAT_TIMEOUT_SECONDS`: например, 30;
- `GIGACHAT_BASE_URL` и `GIGACHAT_OAUTH_URL`: адреса из `.env.example`.

В реальной проверке этого блока использовалась доступная аккаунту `GigaChat-2`.
Это не гарантия её доступности другому проекту и не заявление о бесплатной квоте.
TLS-проверку не отключать; использовать доверенный сертификат сервиса.

Проверка адаптера отдельно от UI (использует внешнюю сеть и квоту аккаунта):

```bash
PYTHONPATH=backend .venv/bin/python -m scripts.gigachat_smoke \
  --env-file /home/linuxoid/Projects/secret.env \
  --output /tmp/medsi-gigachat-check-new.json
```

Команда отправляет фиксированное синтетическое сообщение, проверяет схему,
дословный evidence, `confirmed=false`, ошибку несуществующей модели и сетевой
timeout с намеренно микроскопическим лимитом. Она не сохраняет факты в БД,
не печатает токены/ключи/ответы ошибок провайдера и не перезаписывает отчёт.
Число/формулировки фактов внешней модели могут меняться. Ошибочные JSON,
пустой/выдуманный evidence и OAuth/completion timeout отдельно проверяются
контролируемым транспортом в unit-тестах, а не выдаются за ответы живой модели.

Запуск backend в том же терминале после `source .env`:

```bash
PYTHONPATH=backend .venv/bin/uvicorn app.main:app --app-dir backend \
  --env-file /home/linuxoid/Projects/secret.env --host 127.0.0.1 --port 8000
```

Uvicorn не переопределяет уже экспортированные переменные из env-file. Если
ранее экспортированы пустые `GIGACHAT_AUTH_KEY`/`GIGACHAT_MODEL` из `.env.example`,
перед запуском выполнить `unset GIGACHAT_AUTH_KEY GIGACHAT_MODEL` или оставить
GigaChat-настройки только в одном локальном файле. Значения не выводить.
Для режима без GigaChat достаточно не передавать его env-file; при отсутствии
credentials extraction вернёт контролируемую 503.

В другом терминале:

```bash
npm --prefix frontend run dev -- --host 127.0.0.1 --port 5173
```

Открыть `http://127.0.0.1:5173`. Frontend перенаправляет `/api` в backend на
порту 8000.

## Загрузка синтетического профиля

Операция reset удаляет только записи демонстрационного профиля, включая facts,
events и notifications. Для повторяемости всегда использовать `reset=true`.

```bash
TOKEN=$(curl --fail-with-body -sS http://127.0.0.1:8000/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"user_id":"demo-user","password":"demo-user"}' | \
  .venv/bin/python -c 'import json,sys; print(json.load(sys.stdin)["access_token"])')
curl --fail-with-body -sS http://127.0.0.1:8000/api/v1/demo/load-scenario \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"seed":20261110,"days":21,"reset":true}'
unset TOKEN
```

Ожидается `synthetic=true`, 63 observations, 21 check-in. Seed и история
повторяемы. Перезагрузить UI после импорта/reset, чтобы не показывать старое
состояние React.

## Последовательность текстовой демонстрации

1. Войти `demo-user / demo-user`. Показать отметку synthetic, историю и график.
2. Сохранить «Синтетическая запись самочувствия: сегодня я чувствую слабость,
   она появилась утром.» в поле текстовой записи.
3. Нажать «Извлечь факты». Факты должны прийти от реального GigaChat и оставаться
   неподтверждёнными; одно лишь extraction не сохраняет event/notification.
   Ответ без валидного evidence должен отклоняться, а не приниматься для показа.
4. Проверить текст и цитаты. Исправить «Подтверждённый текст», при необходимости
   сохранить исправление и повторить extraction по исправленному тексту.
   Проверить/исправить категории и полярность, затем «Подтвердить факты».
5. Нажать «Запустить анализ». Он использует актуальные числовые метрики и сохранённые
   подтверждённые факты, а не решение LLM. Ожидается event с evidence и версией
   правил. После исправления F1/F5/F10 текущий день без актуальных чисел даёт
   insufficient_data; старое изменение demo не выдаётся за сегодняшнее.
   Исторический числовой срез задаётся API-параметром as_of. Даже его срабатывание
   не доказывает вклад текста или качество Method C; временная область фактов
   остаётся отдельным finding F2.
6. Выйти и войти `demo-caregiver / demo-caregiver`. Проверить событие,
   уведомление, evidence через API при необходимости; нажать «Прочитать».
   Caregiver имеет только чтение; запись для него должна возвращать 403.
7. Повторить loader с reset, перезагрузить UI, проверить исчезновение старых
   событий/уведомлений и восстановление 63/21 записей.

Эта последовательность описана для следующей записи демонстрации. В текущем
блоке реальным компонентом проверен adapter smoke; полный текстовый UI-путь
именно с реальным GigaChat ещё не записан как успешно пройденный.

Временные метки demo-loader фиксированы: 1–21 октября 2026 года. Анализ по
умолчанию берёт текущий локальный день профиля, поэтому старая история без
сегодняшних чисел даёт `insufficient_data`. Повторяемый исторический числовой
срез: `POST /api/v1/profiles/profile-demo/analysis?as_of=2026-10-21T12:00:00Z`.
Параметр не выбирается через график; новый числовой контракт описан в
`MONITORING.md`. При текущем вводе старые данные могут выйти за 14-дневное
окно. Не менять даты/пороги ради срабатывания; временное согласование настоящего
голоса и числовой истории и жизненный цикл фактов ещё не проверены.

## Голосовой путь: следующий непроверенный участок

Сначала подготовить faster-whisper вне показа. Параметры:
`FASTER_WHISPER_MODEL=base`, `FASTER_WHISPER_DEVICE=cpu`,
`FASTER_WHISPER_COMPUTE_TYPE=int8`, `FASTER_WHISPER_LANGUAGE=ru`.
Первый запуск может скачать модель; не считать загрузку проверкой ASR.

Последовательность для следующего блока:

1. Разрешить доступ к микрофону, нажать «Записать голос», произнести только
   вымышленную фразу о синтетическом профиле, затем остановить запись.
2. Дождаться настоящего результата локального faster-whisper.
3. Сохранить транскрипт, исправить текст, извлечь факты реальным GigaChat,
   проверить и подтвердить их.
4. Анализ → сохранённое событие → caregiver → notification/read.

Ни готовый текст, ни FakeModel, ни загрузка аудиофайла вместо микрофона не
подтверждают весь этот путь. Файл аудио может отдельно проверять ASR, но должен
быть помечен именно как файловая проверка, а не запись в браузере.

## Сеть, резервный режим и восстановление

- GigaChat требует сети, credentials и доступной квоты. OAuth, модель, TLS,
  rate limit и timeout могут прервать extraction. Автоматического локального
  LLM-подменщика нет.
- При 502/503 UI явно показывает «Резервный режим». Новые факты не сохраняются;
  ручной дневник, история и числовой monitoring продолжают работать при
  доступном backend. После восстановления сети повторить extraction вручную.
  Уже подтверждённые факты не удаляются при отказе новой попытки.
- Потеря связи с backend — отдельный отказ: запись в БД не гарантируется,
  интерфейс сообщает об отсутствии связи. Это не офлайн-приложение.
- faster-whisper работает локально после установки/кэширования модели.
  Нет микрофона/ошибка ASR — явно перейти к ручному тексту; это резервный путь,
  не доказательство распознавания речи. Аудио не сохраняется в Git.
- При 422 исправить единицы/значение/дату или evidence, а не ослаблять проверку.
- При 403 использовать правильную роль. При просроченном токене войти снова.
- После перезапуска in-memory теряет данные; для основной демонстрации
  использовать PostgreSQL и миграции. При необходимости повторить loader/reset.

## Подтверждения этого блока

- `demo_checks/gigachat-2026-11-10.json`: реальный GigaChat-2, валидный ответ с
  2 фактами, оба `confirmed=false`; реальная HTTP 404 для неверной модели;
  намеренно вызванный transport timeout. Отчёт не содержит credentials и
  не утверждает, что проверено сохранение в БД.
- До уточнения prompt реальные ответы не проходили критерий положительного
  extraction; один ответ перевёл evidence и был корректно отклонён. После
  уточнения инструкции проверка прошла. Это инженерное исправление, не оценка
  точности извлечения.
- `test_gigachat.py`: ошибки/timeout/JSON/evidence проверены контролируемым
  транспортом. `test_llm_unavailable.py`: при отказах manual/history/monitoring
  доступны, ложные факты/события от extraction не создаются.
- Настоящая запись голоса, ASR по записи, полный real-LLM UI-путь и запись
  конкурсного видео пока не проверены. К ним переходим отдельным блоком.
