# MEDSI Care: правила разработки

## Перед изменением кода

- Прочитать `docs/TECH_SPEC.md` и актуальные документы в `docs/`.
- Проверить `git status` и текущую ветку.
- Для каждой задачи определить критерии готовности до начала реализации.

## Архитектура

- Использовать модульный монолит React + TypeScript + FastAPI + PostgreSQL.
- Не создавать микросервисы без доказанной необходимости.
- Не добавлять универсальный AI-фреймворк.
- GigaChat и faster-whisper подключать только через узкие адаптеры.

## Данные

- Использовать только синтетические медицинские данные.
- Хранить источник, время в UTC и версию алгоритма.
- Не заменять пропуски нулевыми значениями.
- Не помещать секреты в Git, frontend или логи.

## LLM и безопасность

- Ответы LLM считать недоверенными.
- Всегда выполнять Pydantic- и бизнес-валидацию.
- Доказательства должны подтверждаться исходным текстом или пользователем.
- LLM не принимает решения о событиях, порогах, диагнозах и уведомлениях.
- Правила безопасности и monitoring engine выполняются детерминированным кодом.
- Ollama не устанавливать и не добавлять в MVP.

## Тестирование

- Критические правила, доступ, ошибки провайдера и недостаток данных покрывать тестами.
- После каждой задачи запускать релевантные проверки.
- Не подменять рабочие интеграции декоративными заглушками.

## Завершение задачи

- Обновить документацию и контракты API.
- Указать изменённые файлы, команды запуска, тесты и ограничения.
- Проверить diff перед объединением с `main`.
